# otc-valuation-desk 讲解（面试准备用）

这份文档的目标：不看代码，也能把每一步讲清楚。每节最后有"面试可能怎么问"。

## 1. 这个项目在模拟什么

独立估值服务（比如 S&P Global Portfolio Valuations）每天替买方客户做的事：

```
行情质控 -> 构建曲线 -> 自己的模型估值 -> 和独立参照比 -> 和交易对手 mark 比 -> 差异归因 -> 报告
```

客户是虚构的基金（26 笔交易：10 笔 SONIA/SOFR OIS，5 笔 GBPUSD 远期，5 笔 GBPUSD 期权，4 笔 swaption，2 笔 SONIA/SOFR 交叉货币互换）。

| 输入 | 来源 | 真实/模拟 |
|---|---|---|
| GBP 曲线 | 英格兰银行每日 OIS 即期曲线 | 真实 |
| SONIA、SOFR fixing | 英格兰银行、纽约联储 | 真实 |
| USD 曲线 | 美国国债 par 收益率，**当作 SOFR OIS 的代理** | 真实数据，代理用法 |
| GBPUSD 即期 | ECB 参考汇率（EUR/USD ÷ EUR/GBP） | 真实 |
| FX 波动率微笑、swaption 波动率、dealer mark、交易 | — | 模拟 |

**面试可能怎么问**："你的 USD 曲线为什么用国债？"
答：SOFR 互换报价没有免费来源。国债和 SOFR OIS 之间有 swap spread（近年为负），我忽略了它，所以 USD 估值只是示意，项目里每处都标了 proxy。

## 2. 日历和计息

- **Modified Following (MF)**：日期落在非工作日就往后顺延；如果顺延跨了月，就改为往前。
- **计息基准**：GBP 用 ACT/365F，USD 用 ACT/360。同样一年，ACT/360 的年化分数是 365/360，大约多 1.4%。
- **付息日程**：从**未调整的**到期日往回推，每个日期再单独调整。

**我踩过的坑**：最初从调整后的到期日往回推。18 个月的报价到期日是 2028-04-15（周六），MF 调整到 04-13；从 04-13 往回推，中间日期变成 2027-04-13，而正确的是 2027-04-15。和 QuantLib 一对就发现了。修好以后，曲线和 QuantLib 的差距降到 1e-14。

**面试可能怎么问**："ACT/360 和 ACT/365F 搞错会差多少？"
答：固定腿利息放大 365/360 倍。项目里 NBM-IRS-001（5000 万 GBP，4.10%）就是这个原因：dealer mark 比我们低约 10.4 万 GBP。

## 3. OIS 曲线

### 为什么一条曲线就够

有抵押（CSA 现金抵押、隔夜计息）的 SONIA/SOFR 互换，用同一个隔夜指数既**预测**浮动利率，也做**折现**。所以每个币种只需要一条曲线。

### Par rate 公式

一个即期起息的 OIS，浮动腿是隔夜利率按日复利。它的现值可以"伸缩相消"（telescoping）：

```
浮动腿 PV = N × (df(start) − df(end))
```

原因：每一天的远期利率是 f = (df_i / df_{i+1} − 1) / τ，复利乘起来，中间项全部消掉。

固定腿 PV = N × K × Σ τ_i × df(pay_i)。令两边相等，就得到

```
K_par = (df(start) − df(end)) / Σ τ_i × df(pay_i)
```

### Bootstrap（逐个求解）

报价按期限排好，每个报价新增一个节点（pillar）：在这个节点上解出 discount factor，使这笔互换按报价利率刚好估值为 0。前面的节点已经确定，不受影响，因为插值是局部的。

### 插值：log-linear discount factor

在 ln(df) 上线性插值，等价于两个节点之间的远期利率是常数（piecewise flat forward）。简单、稳定，不会产生奇怪的远期。

### 和英格兰银行曲线的差异

我先用 BoE 的零息曲线推出各期限的 par rate，再 bootstrap 回去：

- 所有报价都能精确复现（误差 1e-10）。
- 但在 10 年、15 年、20 年这些稀疏节点之间，零息利率和 BoE 差最多约 0.26bp。原因是 BoE 用平滑样条插值，我用 log-linear。

这正是一个真实的估值差异来源："曲线插值方法不同"。项目里 NBM-IRS-006 的 dealer mark 就埋了这个原因。

**面试可能怎么问**："你怎么构建 SONIA 曲线？为什么用 log-linear？"
答：按上面讲 bootstrap。log-linear 的优点是远期利率不会出现负值或振荡；缺点是远期是阶梯状、不平滑，做远期起息产品时会和用样条插值的人产生差异。

## 4. OIS 互换定价

对每个付息期：

| 情况 | 浮动腿 PV |
|---|---|
| 整个期间在未来 | N × (df(s) − df(e)) |
| 期间已开始（老交易） | N × (A − df(e)) |
| 已结束 | 不计 |

其中 A 是从期初到今天**已实现**的复利因子：

```
A = Π (1 + r_d × n_d / 365)
```

r_d 是每个工作日的 SONIA（真实数据），n_d 是到下一个工作日的自然日数。周五的利率要计 3 天。

为什么是 N × (A − df(e))：到期时的浮动利息 = N × (A × 剩余期间的预期复利 − 1)，剩余期间的预期复利 = df(今天)/df(e) = 1/df(e)。折现回今天乘以 df(e)，就得到 N × (A − df(e))。

今天的 SONIA 要明天早上才公布，所以今天不算在已实现部分里，而是用曲线预测。

**简化**：用的是 0 天 lookback。实际 SONIA 互换常用 5 天 lookback，这一点在 README 里写明了。

**面试可能怎么问**："一笔已经开始的 SONIA 互换怎么估值？"
答：已经过去的那部分用真实 fixing 复利，未来的部分用曲线，固定腿正常折现。然后讲上面的公式。

## 5. FX 远期

用利率平价（CIP），从**即期交割日**（T+2）算起：

```
F(T) = S × [df_GBP(T) / df_GBP(spot)] / [df_USD(T) / df_USD(spot)]
PV(USD) = 方向 × N_GBP × (F − K) × df_USD(T)
```

直觉：GBP 利率高于 USD 时，远期汇率低于即期（远期贴水）。

**面试可能怎么问**："FX 远期为什么从 spot date 算？"
答：即期汇率本身就是 T+2 交割的价格，所以远期要从 T+2 开始用利差推，不能从今天开始。

## 6. FX 期权（Garman-Kohlhagen）

就是 Black-Scholes 加上两个利率。我用的是远期形式：

```
d1 = [ln(F/K) + ½σ²T] / (σ√T),  d2 = d1 − σ√T
看涨 = df_USD(交割日) × N × [F·N(d1) − K·N(d2)]
```

- F 是到**交割日**的远期汇率。
- T 是到**到期日**的时间。
- 波动率是模拟的 ATM 期限结构，在总方差上线性插值。

**和 QuantLib 的差异**：QuantLib 的 GK 引擎从今天算到到期日，不考虑交割滞后。所以两边最多差约 0.016 个 vol 点（1 个月期权最明显；金额最大的是 NBM-FXO-005，约 511 USD）。这不是 bug，是惯例不同，报告里写明了原因。

**面试可能怎么问**："期货期权为什么用 Black-76 而不是 Black-Scholes？"
答：标的是远期或期货价格，它没有持有成本漂移，所以用远期形式（Black-76）。FX 期权用远期形式写，也就把两国利率吸收到 F 里了。

## 7. 风险指标（bump and reprice）

| 指标 | 怎么算 |
|---|---|
| PV01 | 零息曲线平移 +1bp，重新估值，取 PV 的变化 |
| FX delta | 即期 +1% |
| Vega | 波动率 +1 个 vol 点 |

用"重新估值"而不是解析 Greeks：所有产品用同一种方法，也不会因为公式推导出错。

## 8. QuantLib 独立对照

意义：同样的输入（报价、fixing、即期、波动率），换一套独立的日历、日程、bootstrap 和定价引擎。如果结果一致，说明我的模型没写错；如果不一致，要么是 bug，要么是惯例不同，报告里写明是哪种。

结果（2026-10-15）：

| 项目 | 最大差异 | 原因 |
|---|---|---|
| 曲线 | 约 1e-14 | — |
| OIS | 0.79 USD | QuantLib 的 SOFR 日历把 Good Friday 当假日，我用的美国联邦假日不是 |
| Swaption、XCCY、FX 远期 | 不到 1 美分 | — |
| FX 期权 | 0.016 vol 点 | 交割滞后惯例（见第 6 节），1 个月期权最明显 |

这个对照帮我找到了两个问题：

1. 日程从调整后的到期日往回推（第 2 节）。
2. 四笔测试交易写的是调整后的终止日。QuantLib 从那天往回推，会在第一天生成一个 1 天的 stub。真实的交易确认书写的是**未调整**的终止日。

**面试可能怎么问**："你的价格和 QuantLib 对不上，你怎么查？"
答：从下往上拆。先比曲线的 discount factor，再比各期日程，再分别比固定腿和浮动腿，最后逐笔比现金流。我就是这样找到 1 天 stub 的。

## 9. 价格核对（项目核心）

### 容差

取两者中较大的：1000（以 PV 币种计），或者一个产品风险单位的 1/4：

- 互换：0.25bp × PV01
- 期权：0.25 vol 点 × vega
- 远期：即期 2bp 对应的金额

### 归因：逐个替换输入，重新估值

| 原因 | 怎么验证 | 状态 |
|---|---|---|
| 用了前一天的曲线和即期 | 用前一天的真实市场重新估值 | EXPLAINED（已确认） |
| 计息基准错了（GBP） | 固定腿改成 ACT/360 重估 | EXPLAINED |
| 曲线插值不同（GBP） | 改用 BoE 曲线自带的插值重估 | EXPLAINED |
| 方向录反了 | 反方向重估 | EXPLAINED |
| 名义本金录错了 | mark ÷ 我们的价值，是否正好对应一个整数名义本金（PV 和名义本金成正比） | EXPLAINED |
| mark 是 bid/offer 不是 mid | 差异是一小部分 bp 或 vol 点，而且对客户不利 | LIKELY（可能） |
| dealer 的波动率不同 | 差异 ÷ vega | LIKELY |
| 即期取样时间不同 | 差异 ÷ FX delta | LIKELY |

**确认的标准**：重估后能消除至少 90% 的差异；如果多个原因都符合，取残差最小的那个。只有"几乎正好"才算确认，所以碰巧接近的原因会输给真正的原因。

**为什么有的只能是 LIKELY**：波动率、即期时间这类原因，大小是从风险指标反推出来的。只要除一下 vega，总能"解释"差异，所以它们只是给 dealer 的问题，不是结论。

**检验力不足（power guard）**：一笔接近平价的互换价值接近 0，方向反了、名义本金错了，价值都几乎不变，没法从价值上看出来。所以价值小于容差 2 倍时，不做这两项测试，报告提示"去核对确认书"。NBM-IRS-005 就是这种情况。

**未解释**：所有假设都不符合，就标 UNEXPLAINED，升级处理，向 dealer 要完整的估值输入。

**测试**：26 笔 mark 里，15 笔埋了差异原因，11 笔是干净的。归因找到了全部 15 个差异，也没有把 11 笔干净的误判为问题。面试时要主动说明：答案是我自己生成的，所以这个测试有循环性，验证的是逻辑，不代表真实世界的准确率。归因代码看不到答案表，答案表只用于测试。

**面试可能怎么问**："银行的估值单和你的对不上，你怎么处理？"
答：

1. 先看差异是否超过容差。
2. 超过的话，按常见原因逐个排查：快照日期和时间、计息和日程惯例、曲线构建方法、录单（方向、名义本金）、bid/mid、波动率。
3. 能用重估确认的，就是确认的结论；只能反推的，要向 dealer 提问核实。
4. 都解释不了，就升级。

可以拿项目里的例子讲。

## 9a. Swaption（Bachelier / 正态模型）

利率可以为负、而且利率的波动更接近"每年多少 bp"而不是百分比，所以市场用正态波动率报价（单位 bp）。

```
远期互换利率 S = (df(start) − df(end)) / A,   A = Σ τ_i × df(pay_i)（年金）
d = (S − K) / (σ√T)
payer = N × A × [(S − K)·Φ(d) + σ√T·φ(d)]
```

- receiver 把 (S − K) 换成 (K − S)，Φ(d) 换成 Φ(−d)。
- **payer − receiver = N × A × (S − K)**，就是一笔远期起息互换的价值（测试里验证了）。
- 波动率来自期限 × 标的期限的网格（模拟数据），双线性插值。
- 和 QuantLib 的 `BachelierSwaptionEngine` 结果一致到 1 美分以内。

**面试可能怎么问**："为什么 swaption 用正态模型不用 Black？"
答：低利率或负利率时，lognormal 模型无法处理，而且利率的实际变动更接近绝对 bp。另外，正态 vol 乘以年金和 √T，可以直接换算成美元风险，便于沟通。

## 9b. FX 波动率微笑（vanna-volga）

FX 市场每个期限报三个数：ATM（delta 中性跨式）、25-delta risk reversal（RR）、25-delta butterfly（BF）。

1. 先换算成三个支点的波动率：σ25C = ATM + BF + RR/2，σ25P = ATM + BF − RR/2。这是"smile strangle"简化，实际 broker strangle 更复杂，README 里写明了。
2. 再由 delta 反解出三个支点的执行价（用 forward delta）：
   - ATM：K = F·exp(½σ²T)
   - 25D call：K = F·exp(−N⁻¹(0.25)·σ√T + ½σ²T)
   - 25D put：K = F·exp(−N⁻¹(0.75)·σ√T + ½σ²T)
3. 任意执行价的波动率用 vanna-volga 插值（Castagna-Mercurio 二阶近似）。思路是：用三个支点期权组合复制 vega、vanna、volga，算出所需的成本，再把它换算成波动率。

测试验证了：三个支点的波动率能精确复现；RR 为负时，GBP put 一侧更贵；两翼高于中间。

**面试可能怎么问**："risk reversal 是负的说明什么？"
答：市场对 GBP 下跌的保护（put）需求更大，愿意多付波动率。

## 9c. 交叉货币互换（SONIA vs SOFR）

一条腿收 GBP SONIA（加点差），另一条腿付 USD SOFR。名义本金固定，期初和期末各交换一次本金，每季度付息。

关键结论：**一条浮动腿加上按面值交换的本金，现值等于 0（伸缩相消）**。所以在没有基差的模型里，交叉货币互换的价值只来自三处：

- 点差的年金
- 本期已经实现的复利
- 本金在成交时按当时汇率定下、之后汇率变动带来的价值（这部分最大）

项目里 NBM-XCY-001 的价值主要来自 GBPUSD 的变化，PV01 几乎为 0，FX delta 很大。

**局限**：真实市场有 GBP/USD 交叉货币基差。没有免费数据，所以模型里基差为 0，README 里写明了。

## 9d. 月末估值变动归因（month-end explain）

两个日期之间的价值变化，按顺序一块一块替换市场数据，每一步都完整重估：

1. **carry**：日期挪到月末，曲线按日期保持不变（远期实现），即期和波动率不变。真实的 SONIA/SOFR fixing 在这一步进入。
2. GBP 利率换成月末的
3. USD 利率换成月末的
4. 即期汇率换成月末的（GBP 计价交易换算成 USD 的影响也在这一步）
5. 波动率（模拟、不变，所以是 0）
6. 当月新交易

2026-08-28 到 2026-09-30（真实行情：GBP 5 年 +36bp，USD 5 年 +60bp，GBPUSD −2.2%）：

| 步骤 | 金额 |
|---|---|
| carry | −80k |
| GBP 利率 | +229k |
| USD 利率 | −66k |
| 即期汇率 | −158k |
| 新交易 | −128k |
| 残差 | 0 |

**顺序依赖**：先换 FX 还是先换利率，会让 3–7k 在两步之间移动，这就是交叉效应。报告里同时给出了反向顺序的结果。

现金流：期间没有付息、交割或到期（代码检查过）。如果有，会提示"未建模"，而不是悄悄漏掉。

**面试可能怎么问**："客户问为什么这个月估值降了 20 万，你怎么解释？"
答：按上面的分步结果讲：利率上升让付固定的互换赚钱，GBP 贬值让多头 GBP 的远期和 XCCY 亏钱，期权有时间价值损耗，当月还新做了两笔交易。

## 11. 简历上的写法规则

- 必须写 "personal build"、"built with AI coding agents"，模拟的部分要写明。
- 真实数据来源要写准确。
- 数字以 FROZEN-FACTS 为准，比如"finding all 15 planted breaks and clearing the 11 clean marks"、"matches a QuantLib rebuild to under $1 on all swaps and swaptions and 0.02 vol points on FX options"。不要说 machine precision（有一笔 USD 互换差 0.79 美元），也不要说"独立估值"（QuantLib 用的是同一套输入数据，独立的只是实现）。
